# TaskForge: работа вдвоём

У вас один общий проект и один репозиторий GitHub. У каждого на компьютере должна быть **полная копия проекта**, но вы изменяете разные части. Папки `src/ui` и `src/logic` сами по себе не запускаются.

Готовый MVP — общая стартовая заготовка, созданная с помощью AI. Дальнейшие изменения каждый делает и отправляет со своего аккаунта. В отчёте указывайте свою часть работы, результаты проверок и ссылки на коммиты или pull request (PR — запрос на объединение изменений).

## Кто за что отвечает

| Участник | Его файлы | Его работа |
| --- | --- | --- |
| 1 — интерфейс | `src/ui/`, `src/App.jsx`, `src/main.jsx` | Экраны, карточки, формы, мобильная версия, подключение логики к интерфейсу |
| 2 — логика и AI | `src/logic/`, `tests/` | Рейтинг, локальный AI-анализ, проверка полей, демонстрационные данные, сохранение и тесты |

`package.json`, `package-lock.json`, `vite.config.js` и `README.md` меняйте по договорённости: сначала напишите друг другу. Не переименовывайте экспортируемые функции и поля без согласования — интерфейс использует их.

Личные отчёты: участник 1 заполняет `docs/reports/member-1.md`, участник 2 — `docs/reports/member-2.md`.

## Первичная загрузка — один раз

1. Один участник создаёт пустой репозиторий GitHub и приглашает второго участника в collaborators. Второй принимает приглашение.
2. Установите Git, если команда `git --version` не работает. После установки откройте новое окно PowerShell.
3. В полной папке TaskForge проверьте, что есть `.gitignore`. Не загружайте `node_modules`, `dist`, пароли, токены и `.env`.
4. Только если эта папка ещё **не является Git-репозиторием**, первый участник выполняет следующие команды. Замените имя, email и URL своими значениями. Email должен быть связан с вашим аккаунтом GitHub; можно использовать свой GitHub no-reply email.

```powershell
git init -b main
git config user.name "ВАШЕ ИМЯ"
git config user.email "ВАШ EMAIL GITHUB"
git add src tests public docs index.html vite.config.js package.json package-lock.json README.md TEAMWORK.md .gitignore .npmrc
git status
git commit -m "chore: add shared AI-assisted MVP scaffold"
git remote add origin "URL ВАШЕГО ПУСТОГО РЕПОЗИТОРИЯ"
git push -u origin main
```

Перед `git commit` проверьте список файлов в `git status`. Если репозиторий уже существует или на GitHub уже есть файлы, не повторяйте первоначальную загрузку и не используйте принудительную отправку (`--force`).

Друг скачивает полную копию в новую папку, а не копирует только `src/logic`:

```powershell
git clone "URL ВАШЕГО РЕПОЗИТОРИЯ" TaskForge-team
cd TaskForge-team
git config user.name "ИМЯ ВТОРОГО УЧАСТНИКА"
git config user.email "EMAIL ВТОРОГО УЧАСТНИКА В GITHUB"
npm.cmd install
```

## Каждый работает в своей ветке

Начинайте с актуальной `main` и без незаписанных изменений. Команды выполняются в полной папке проекта.

```powershell
git switch main
git pull --ff-only
```

Участник 1 создаёт ветку `git switch -c feature/ui-search`, участник 2 — `git switch -c feature/logic-tests`. Для следующей задачи создавайте новую ветку с новым понятным именем.

После своих изменений проверьте проект:

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run dev
```

Откройте адрес, который показан в терминале. Для остановки сервера нажмите `Ctrl+C`. В браузере пройдите изменённый сценарий; успешные тесты не заменяют проверку интерфейса.

Участник 1 добавляет **только изменённые им файлы** из `src/ui`, `src/App.jsx`, `src/main.jsx` и свой отчёт. Пример для задачи поиска:

```powershell
git add src/App.jsx docs/reports/member-1.md
git diff --cached
git commit -m "feat: add catalog text search"
git push -u origin feature/ui-search
```

Участник 2 для задачи новых тестов:

```powershell
git add tests/domain.test.js docs/reports/member-2.md
git diff --cached
git commit -m "test: cover rating groups and unsafe links"
git push -u origin feature/logic-tests
```

Это примеры: добавляйте изменённые вами файлы и описывайте полученный результат.

После отправки каждый открывает PR из своей ветки в `main`, кратко описывает изменения и проверки. Друг просматривает PR. Объединяйте PR по одному; для сохранения отдельных коммитов выбирайте обычное объединение с merge commit, если оно разрешено. После объединения оба обновляют `main`. Если появились конфликты, не затирайте чужой файл: вместе проверьте различия.

## Небольшие задачи на следующий этап

Это предложения для будущей работы, а не уже выполненные изменения.

**Участник 1:**

- Добавить поиск по названию и потребности в каталоге. Проверка: запрос «продажи» находит соответствующую демонстрационную задачу, очистка поиска возвращает список.
- Добавить кнопку сброса фильтров каталога. Проверка: тема, готовность и поиск возвращаются к исходным значениям.
- Проверить создание задачи, карточку и отклик на ширине 360 px; исправить найденные проблемы и приложить скриншоты к своему PR.

**Участник 2:**

- Добавить табличные тесты каждого отдельного веса рейтинга: 20, 20, 15, 15, 10, 10, 10; проверить неполные парные группы.
- Дополнить тесты AI-анализа явно указанными контактом и форматом взаимодействия; проверить, что остальные неизвестные поля остаются пустыми.
- Дополнить тесты ссылок отклика схемами `data:` и `ftp:`, а сохранения — ошибкой чтения localStorage. При обнаружении ошибки исправить её вместе с тестом.

## Отчёт каждый час

В конце каждого из пяти часов каждый заполняет строку своего отчёта: что реально сделал, как проверил, ссылка на коммит/PR или доказательство проверки. Незавершённое помечайте «в работе», проблемы — «заблокировано». Число коммитов не заменяет описание личного вклада.
