# TaskForge — практические задачи бизнеса

Работающий MVP для HackAlem: описание задачи → локальный AI-анализ → уточнения → редактируемая карточка → рейтинг → публикация → предложение команды → ручное решение бизнеса.

Стек: React 19 + Vite 8 + JavaScript, обычный CSS, иконки Lucide. Приложение целиком работает в браузере. Backend, регистрация и база данных не нужны.

## Работа вдвоём

Проект разделён на две зоны: `src/ui/` — интерфейс участника 1, `src/logic/` и `tests/` — логика и тесты участника 2. Связующие файлы `src/App.jsx` и `src/main.jsx` ведёт участник 1; изменение названий полей и функций согласовывайте вдвоём. Это зоны ответственности для дальнейшей работы, а не утверждение об авторстве готовой заготовки.

Каждый работает с полной копией одного репозитория. Инструкция по веткам и совместным изменениям: [TEAMWORK.md](TEAMWORK.md). Шаблоны почасовых отчётов находятся в `docs/reports/`.

## Быстрый запуск в Windows

Нужен Node.js 22.13+; для Vite также подходит Node.js 24+. В PowerShell, открытом в папке проекта:

```powershell
npm.cmd install
npm.cmd run dev
```

Откройте адрес из терминала (обычно http://127.0.0.1:5173). Если порт занят, Vite предложит следующий. Адрес в браузере должен совпадать с адресом терминала. Оставьте терминал открытым; Ctrl+C останавливает сервер разработки. `npm.cmd` помогает обойти блокировку `npm.ps1` в PowerShell без изменения политики безопасности.

На macOS/Linux используйте `npm install` и `npm run dev`.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`build` создаёт статические файлы в `dist/`. `preview` показывает эту сборку. Перед публикацией собирайте проект заново. Достаточно любого статического хостинга; все переходы реализованы внутри приложения.

## Что реализовано

- Каталог с сортировкой по рейтингу и фильтрами по теме и готовности. Новые темы автоматически попадают в фильтр.
- Конструктор с исходным описанием, минимум тремя уточняющими вопросами и редактируемой карточкой.
- Пересчёт 0–100 во время ввода, расшифровка и список недостающих полей.
- Ручное подтверждение публикации. Повторное редактирование опубликованной задачи через её карточку или кабинет бизнеса.
- Отклики с названием команды, идеей, планом, сроком и ссылкой на прототип. Количество откликов не ограничивается.
- Кабинет бизнеса: все предложения, ссылки и ручные кнопки «Выбрать» / «Отклонить». Решение можно изменить. Другие предложения при этом не меняются.
- Пять профилей команд: интересы, навыки и технологии.
- Пять исходных описаний, пять задач с рейтингами 100, 80, 55, 30, 0 и пять откликов. Все данные синтетические; ссылки example.com — демонстрационные заглушки.
- Понятные состояния пустого списка, ошибок и успешных действий. Навигация доступна на телефоне.

## Формула рейтинга

Пустая строка и строка из пробелов дают 0. Для составной группы баллы начисляются, только когда заполнены **оба** поля. Длина текста сама по себе не увеличивает рейтинг. Это оценка полноты, а не качества решения.

| Группа | Баллы |
| --- | ---: |
| Контекст **и** потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт **и** формат взаимодействия | 10 |

0–39 — «Черновик», 40–69 — «Рабочая», 70–89 — «Готовая», 90–100 — «Приоритетная».

До публикации показывается предварительный рейтинг. Нажатие «Подтвердить и опубликовать» подтверждает сведения и обновляет каталог. В каталоге опубликованные задачи сортируются по убыванию рейтинга. Низкий балл не запрещает публикацию или отклик. Для публикации нужны только название, тема и потребность.

## Локальная имитация AI

Внешних API, ключей и ML-моделей нет. Функция `analyzeDescription` проверяет наличие полей и составляет вопросы по правилам. Список фиксируется при запуске анализа, поэтому вопросы не исчезают при вводе.

Свободный текст сохраняется как потребность. Название берётся из первой строки введённого текста; контекст, критерии и прочие неизвестные сведения не придумываются. Явные строки формата «Название: …», «Контекст: …», «Пользователи: …» переносятся в соответствующие поля. Если все поля заполнены, задаются три вопроса для подтверждения существующих сведений. Ответы переносятся дословно и остаются редактируемыми.

Контракт для замены адаптера в будущем:

```js
// Вход
analyzeDescription(rawDescription, existingFields)
// Выход
{ fields: { title, context, need, users, data, constraints,
  expectedResult, successCriteria, contact, interactionFormat, topic, ... },
  questions: [{ key: 'users', text: 'Кто будет пользоваться решением?' }, ...] }
```

Пример промпта (также экспортирован как `AI_PROMPT`): «Проверь полноту бизнес-задачи. Задай не менее трёх вопросов о недостающих сведениях. В карточку переноси только явно введённые данные; неизвестные поля оставляй пустыми. Не назначай команду. Верни JSON: { fields: { ... }, questions: [{ key, text }] }».

`validateAnalysis` проверяет структуру результата. При некорректном ответе показывается ошибка; доступно заполнение карточки вручную. Исходный текст остаётся в форме.

## Сохранение и ограничения MVP

Задачи, предложения и решения хранятся в `localStorage` под ключом `taskforge.v2`. Старые ключи `taskforge-tasks` и `taskforge-proposals` считываются при первом переходе на новую версию и не удаляются. Незавершённый конструктор живёт в текущей вкладке до перезагрузки.

При повреждённом хранилище показываются демо-данные и предупреждение; исходная запись не перезаписывается. При отказе записи изменения остаются только в памяти, о чём сообщает интерфейс.

Данные привязаны к браузеру и точному адресу сайта (включая порт). Другой браузер или другой порт открывает отдельное хранилище. В режиме демонстрации бизнес и команды используют одну вкладку; это не многопользовательский сервис и не система разграничения доступа. Кнопка «Редактировать как бизнес» — демонстрационное переключение роли.

В браузерах с поддержкой WebMCP доступны `list_catalog_tasks` (чтение) и `start_task_creation` (открытие неопубликованного черновика). Обычный интерфейс работает независимо от WebMCP.

## Демонстрация за 5 минут

1. **0:00–0:40.** В каталоге покажите пять задач, фильтры и задачу «Нужно улучшить продажи» с 0/100. Она доступна для отклика.
2. **0:40–1:50.** Создайте задачу с тем же описанием. Запустите анализ. Ответьте минимум на три вопроса полными предложениями.
3. **1:50–3:00.** Перейдите к карточке. Укажите контекст, пользователей, данные, ограничения, результат, измеримые критерии, контакт и формат связи. Покажите рост баллов и их расшифровку.
4. **3:00–3:30.** Подтвердите публикацию. Новая задача появляется в каталоге на позиции по рейтингу.
5. **3:30–4:20.** Откройте задачу, выберите демо-команду или введите свою. Отправьте идею, план, срок и ссылку `https://example.com/my-prototype`.
6. **4:20–5:00.** В кабинете бизнеса выберите задачу в фильтре и вручную примите отклик. Перезагрузите страницу и покажите, что решение сохранилось.

## Ручные проверки перед защитой

- Пустое описание не проходит анализ; пробелы не дают баллы.
- Поле ответа не исчезает при первом символе; назад/вперёд сохраняет текущие ответы.
- Контакт без формата связи не даёт 10 баллов; контекст без потребности не даёт 20.
- Задача с новой темой видна в соответствующем фильтре. Задача с нулевым рейтингом допускает отклик.
- Некорректная ссылка в отклике блокируется; принятие одной команды не меняет остальные предложения.
- На узком экране доступны каталог, создание, кабинет и команды.
